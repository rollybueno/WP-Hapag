# Block pattern inventory

## Summary

The complete prototype requires **22 registered block patterns**.

This count covers unique, reusable page compositions. It deliberately excludes:

- The site header and footer, which should be WordPress template parts.
- Entire templates, which belong in `templates/` rather than `patterns/`.
- Individual buttons, headings, images, separators, and other core blocks.
- Minor card variations that can be controlled through block styles or Query Loop context.

Alongside the patterns, the theme will need **2 template parts** and **6 primary templates**.

| Type | Count |
|---|---:|
| Registered patterns | **22** |
| Template parts | 2 |
| Primary templates | 6 |

## Naming convention

Pattern slugs should use the theme namespace and a descriptive kebab-case name:

```text
hapag/home-hero-collage
hapag/recipe-query-grid
hapag/single-recipe
```

Suggested pattern categories:

- `hapag-home`
- `hapag-content`
- `hapag-recipes`
- `hapag-calls-to-action`

## Dynamic content requirements

The patterns assume the following WordPress data:

| Data | Likely source |
|---|---|
| Title, excerpt, author, date, featured image, content | WordPress core post fields |
| Recipe category and journal category | Taxonomies |
| Preparation time, cooking time, servings, difficulty, rating | Post meta or block attributes |
| Ingredients and instructions | Recipe block attributes or structured post meta |
| Reading time | Computed value or post meta |
| External ordering URL | Theme setting, navigation link, or pattern-level editable URL |
| Newsletter form | Form plugin block or provider embed |

## Pattern implementation order

Recommended order minimizes rework:

1. Establish `theme.json`, typography, spacing, colors, buttons, and image treatments.
2. Build the header and footer template parts.
3. Build shared card markup inside `hapag/featured-recipes`, `hapag/recipe-query-grid`, and `hapag/related-posts`.
4. Build the homepage patterns.
5. Build single-post patterns, including the structured recipe block.
6. Build page and archive patterns.
7. Build the full-width editorial patterns and 404 pattern.
8. Assemble templates and verify desktop, tablet, and mobile behavior in the Site Editor and front end.

## Registration guidance

Patterns that contain Query Loops, Post Content, Post Featured Image, Comments, or other context-aware blocks should generally be registered from PHP files in `patterns/`. Patterns that are purely editorial compositions can also live there so they appear consistently in the Site Editor.

Do not hard-code attachment IDs from the development site. Pattern preview images may use bundled assets, but inserted content images should be replaceable blocks and dynamic featured images should use `core/post-featured-image`.
